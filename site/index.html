01 / Идея

Изменять осознанно.
Проверять воспроизводимо.

В SedravaSQL исследуются механизмы, которые помогают избежать неожиданных изменений и оставляют проверяемую историю действий. Это инженерная цель, а не обещание абсолютной безопасности.

01 — PREVIEW

Сначала увидеть

План операции перед записью и подтверждение опасных действий. Удаление требует отдельного согласия.

02 — REVISION

Не потерять изменения

Проверка ожидаемой ревизии (CAS) отклоняет запись, если данные успели измениться.

03 — AUDIT

Разобраться позже

Аудит и ключи идемпотентности записываются в одной транзакции вместе с управляемым изменением.

02 / Состояние разработки

Без обещаний вместо кода.

Ниже — подтверждённые возможности SQLite-прототипа, NativeLog и кандидата A24/A26; отдельно указаны ограничения.

Реализовано и проверяется

  • ✓Исполняемый прототип на Rust, SQLite, WAL
  • ✓Ограниченный типизированный key/value API
  • ✓Предпросмотр, CAS и подтверждение удаления
  • ✓Аудит, повтор запросов по ключу идемпотентности
  • ✓Проверки конкурирующих записей и SQLite Backup API
  • ✓NativeLog: типизированные таблицы, SELECT, INSERT, UPDATE, DELETE, JOIN, агрегаты, вторичные индексы, внешние ключи и ограниченные транзакции
  • ✓B24/B25: отдельное изменяемое страничное хранилище, redo WAL, кеш, разделение узлов B+Tree
Объём доказательств и ограничения описаны в репозитории.

Пока не готово

  • —Произвольные SQL-запросы и полноценные реляционные схемы
  • —Сетевой SQL-сервер и промышленная эксплуатация
  • —Роли пользователей, репликация и шифрование
  • —Гарантированное восстановление после физической потери питания
  • —Стабильный API и обязательства по совместимости
Не используйте текущие сборки для ценной информации.

04 / Исследования

Свой движок уже работает.

Помимо действующего SQLite-прототипа реализован экспериментальный механизм хранения NativeLog без зависимости от SQLite. SQL использует журнал NativeLog B28. B25 — ранний отдельный прототип; B29–B31 — отдельное COW-хранилище, ещё не SQL backend.

A1

Контракт пакетных операций

Общий экспериментальный интерфейс транзакций и тесты для NativeLog и изолированного SQLite-адаптера.

B1

Исследование восстановления

План только для чтения и копирование подтверждённого префикса журнала без изменения источника.

B2

Офлайн-копирование

Проверяемая копия исправного остановленного журнала. Это пока не онлайн-бэкап.

B3

Детерминированный снимок

Детерминированный snapshot исправного остановленного журнала, содержащий состояние и историю квитанций. Это не online-checkpoint.

B4

Восстановление в новый журнал

Из проверенного snapshot восстанавливается побайтово исходный журнал и квитанции запросов. Без автоматического переключения базы, compaction и гарантий production.

B16–B23

Ограниченный SQL

Таблицы, агрегация, соединения, индексы, внешние ключи, последовательные транзакции с историческими квитанциями.

B24–B25

Страницы и дерево

4096-байтовые страницы, redo WAL, кеш 32 страниц, динамические разделения дерева и контролируемое восстановление после выхода процесса. Отдельный прототип, не подключён к SQL.

Состояние разработки

Контрольная точка A28 · 27 ноября 2026

Публичный релиз 0.1.0-alpha.1 не изменён. Интеграционный кандидат NativeLog включает B37 и добавочные миграции A24. Проверены 21 тест основного пакета, 73 теста нативного движка и связка с Sedrava: 85 Rust-тестов и 319 HTTP-запросов. Обе независимые проверки Forgejo завершены успешно.

Миграции: CREATE TABLE, CREATE INDEX, ALTER TABLE ADD FOREIGN KEY, один DDL на версию, SHA-256 истории и атомарная запись каталога вместе с версией. Нет произвольного ALTER, DROP, автоматического отката или baseline заполненной базы.

Исследования B32–B36 реализованы отдельно; COW не стал основным SQL-хранилищем по итогам сравнительных испытаний. B37 — внутренний интерфейс хранения, NativeLog остаётся основным SQL backend. Один писатель, ограниченный журнал, только тестовые данные.

Единый комплект A28: два нативных CLI, 4 732 501 байт, проверка автономной установки на Ubuntu 24.04 x86-64. Пока не опубликован как новый релиз.

05 / Измерения · 24.11.2026

Базовое сравнение с SQLite (до B26–B28).

Три независимых базы по 300 строк, Rust API внутри процесса, синхронная запись и квитанции. Медианы, мс: INSERT 1,313 / 1,453; поиск PK 0,029 / 0,020; категория 0,772 / 0,173; агрегация 0,756 / 0,074 (SedravaSQL / SQLite). Выборка и агрегация требуют оптимизации. Различаются семантика квитанций и хранение истории; это не промышленный benchmark.
