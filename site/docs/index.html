Начните с проверяемого.

Краткое русскоязычное руководство по рабочему SQLite-прототипу SedravaSQL и отдельному экспериментальному журналу NativeLog. Полные спецификации и тесты публикуются в GitHub.

Экспериментальное ПО. Ни текущий SQLite-прототип, ни независимый NativeLog не предназначены для ценных или производственных данных. SedravaSQL пока не является полноценным SQL-сервером.

Два направления разработки

0.1.0-alpha.2 · SQLite

Работающий встраиваемый прототип на Rust: типизированное key/value API, аудит, CAS, идемпотентность и резервирование через SQLite Backup API.

NativeLog · исследование

Отдельный Rust-движок без SQLite: append-only журнал с многоключевыми транзакциями, проверкой ревизий, журналом квитанций и экспериментами B1–B28.

Установка и сборка из исходников

Готовый Linux x86_64 alpha: три CLI и SHA-256. Установка в отдельный каталог без Python и Rust. Проверено на Ubuntu 24.04; не для важных данных.

Нужны Git, Rust не ниже 1.85, Cargo и C-компилятор. Сборка для Linux x86_64 проверялась на VDS; работа на других системах не подтверждается этой проверкой.

git clone https://github.com/VasiliiBabkin/sedravasql.git
cd sedravasql
cargo build --locked
cargo test --locked --all-targets
python3 scripts/verify_local.py

Python применяется к проверочному скрипту, а не нужен исполняемому файлу SedravaSQL для работы.

Первый запрос — на временной базе

Пример относится к SQLite-прототипу, не к собственному NativeLog. Используйте отдельную тестовую директорию.

mkdir -m 700 -p /tmp/sedravasql-demo
DB=/tmp/sedravasql-demo/data.sqlite
BIN=./target/debug/sedravasql
"$BIN" init "$DB"
"$BIN" plan-put "$DB" demo greeting "Привет"
"$BIN" put "$DB" demo greeting "Привет" \
  --expect 0 --request-key example-request-0001
"$BIN" get "$DB" demo greeting
"$BIN" verify "$DB"

Операция удаления требует отдельного подтверждения. Отложенные либо неподдерживаемые функции не объявляются работающими.

NativeLog: SQL и исследования хранения

B1 · Восстановление префикса

Ручной план и копирование проверенного префикса оборванного журнала в новый файл.

B2 · Офлайн-копия

Копия полного исправного журнала в новый файл только при соответствии подтверждённой SHA-256.

B3 · Snapshot

Сохранение текущего состояния и квитанций в отдельный детерминированный формат SEDRSNP1.

B4 · Restore

Воссоздание полного исходного журнала из snapshot в новый файл с проверкой побайтовой SHA-256.

B16–B28: SQL и исследования страниц

NativeLog выполняет SELECT, INSERT, UPDATE, DELETE, агрегаты, ограниченный JOIN, GROUP BY, HAVING, DISTINCT, вторичные индексы, внешние ключи и последовательные транзакции B23. Записи SQL фиксируются в журнале; отдельные B24/B25 используют redo WAL и B+Tree, но ещё не являются его backend.

cargo build --release --locked --manifest-path native-engine/Cargo.toml
BIN=./native-engine/target/release/sedravasql-native-preview
DIR=$(mktemp -d)
"$BIN" init "$DIR/demo.log"
"$BIN" sql "$DIR/demo.log" "CREATE TABLE Items (id TEXT PRIMARY KEY, price INT)" schema-request-0001
"$BIN" sql "$DIR/demo.log" "INSERT INTO Items (id,price) VALUES ('a',10)" insert-request-0001
"$BIN" sql "$DIR/demo.log" "SELECT id,price FROM Items"
"$BIN" verify "$DIR/demo.log"

Используйте только тестовые данные. SQL B23 · B25 · Измерения.

Выпуск A30 · 28 ноября 2026

Публичный alpha-релиз 0.1.0-alpha.2 опубликован. NativeLog 0.0.2 включает B37 и добавочные миграции A24. Проверены 21 тест основного пакета, 73 теста нативного движка и связка с Sedrava: 85 Rust-тестов и 319 HTTP-запросов. Обе независимые проверки Forgejo завершены успешно.

Миграции: CREATE TABLE, CREATE INDEX, ALTER TABLE ADD FOREIGN KEY, один DDL на версию, SHA-256 истории и атомарная запись каталога вместе с версией. Нет произвольного ALTER, DROP, автоматического отката или baseline заполненной базы.

Исследования B32–B36 реализованы отдельно; COW не стал основным SQL-хранилищем по итогам сравнительных испытаний. B37 — внутренний интерфейс хранения, NativeLog остаётся основным SQL backend. Один писатель, ограниченный журнал, только тестовые данные.

Единый комплект A30: три CLI, 6 097 061 байт. Автономная установка проверена на Ubuntu 24.04 x86-64. Опубликован в GitHub и на официальном сайте.

Экспериментальный CLI

Ниже приведена демонстрация для заранее созданных тестовых файлов в приватной директории. Записывающий процесс должен быть остановлен. Это не команда для восстановления работающей базы.

cargo build --locked --manifest-path native-engine/Cargo.toml
BIN=./native-engine/target/debug/sedravasql-native-preview
"$BIN" backup-plan /path/to/test.slog
"$BIN" snapshot-create /path/to/test.slog \
  /path/to/new.snap FULL_64_DIGIT_SOURCE_SHA256
"$BIN" snapshot-verify /path/to/new.snap
"$BIN" restore-copy /path/to/new.snap \
  /path/to/new-restored.slog FULL_64_DIGIT_SNAPSHOT_SHA256
"$BIN" verify /path/to/new-restored.slog

Подставляйте точные значения SHA-256 из соответствующих планов и проверок. Не используйте пути к работающей базе, не удаляйте файлы блокировок и не восстанавливайте поверх исходника.

Воспроизводимые тесты

Тесты B1–B4 запускаются на изолированных временных файлах. Они проверяют контрольные суммы, квитанции запросов, ревизии и отказы на повреждённых данных. Это не заменяет испытаний физических сбоев накопителя.

cargo test --locked --all-targets
cargo test --locked --manifest-path native-engine/Cargo.toml --all-targets
python3 scripts/verify_local.py
# Последующие native CLI-тесты требуют сборки соответствующего бинарника.
Отчёт о проверках Реестр утверждений

Что пока не реализовано

Есть ограниченный SQL для типизированных таблиц; полного диалекта SQL и сетевого SQL-сервера нет. В NativeLog ещё нет онлайн-snapshot, автоматического переключения активной базы, compaction, подключённого к SQL динамического дискового B+Tree или доказанной устойчивости к физической потере питания.

Восстановление B4 реконструирует всю историю журнала и потому не уменьшает его размер. Экспериментальные команды B1–B4 работают с отдельно созданными файлами; эксплуатацию на реальных пользовательских данных не рекомендуем.
