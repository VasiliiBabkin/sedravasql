# B32 — безопасное повторное использование страниц COW
Исследование на основе B31 a98e709cc591057298818d0972c12cf020054295; не SQL backend и не релиз.

Новый opt-in API `CowTree::commit_reusing` проверяет текущий заголовок, точную длину файла и полный граф владения (включая overflow) без доверия старому кешу. Старый `commit` остаётся append-only. После CAS и предварительной сериализации временные ID переназначаются в порядке «дети раньше родителей». Выбираются только недостижимые из опубликованного корня ID, строго выше максимальной ссылки узла; иначе добавляется новая страница. Формат SEDRHDR3 и правило убывающих ссылок сохраняются. Страница 0 и все достижимые страницы защищены. Перед переиспользованием синхронизируется каталог; данные fsync → staging head fsync → rename → fsync каталога. Кеш очищается после публикации. При неопределённом I/O исходе экземпляр poisoned.

На VDS пять целевых тестов PASS, включая служебный child: 100 обновлений одной записи с периодическими reopen, 3 data pages (12 KiB, вместе с head 16 KiB); 96 ключей с 48 обновлениями, overflow/tombstones, сравнение с append-only oracle и compact/reopen; отказ CAS без записи; выявление повреждения живой страницы при ранее заполненном кеше; реальные process exits после sync pages, sync stage, rename с проверкой неизменности старой живой страницы. Лог: [targeted-tests](../evidence/benchmark/b32-page-reuse-2026-11-25/targeted-tests.log).

Контроль совместимости текущего стека: A17–A21, 63 HTTP-запроса PASS с ранее собранным Sedrava B28 и собранным в research worktree SQL CLI. Это контроль прежней интеграции, не интеграция COW. [Лог](../evidence/benchmark/b32-page-reuse-2026-11-25/language-smoke.log).

Ограничения: полный обход перед каждой reuse-транзакцией может быть дорогим; из-за убывающих ID не все свободные страницы пригодны, файл может расти, in-place vacuum не реализован. Старые снимки, независимые читатели и произвольная подмена файлов не поддерживаются. Тесты выхода процесса не доказывают сохранность при физическом отключении питания. Автоматическое снятие stale lock/stage не добавлено. Не подключать к SQL до проверки долговременных квитанций, миграции, crash/recovery и производительности.

Воспроизведение: cargo test --manifest-path native-engine/Cargo.toml --locked --offline --test cow_b32.
