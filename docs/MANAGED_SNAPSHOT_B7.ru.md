# SedravaSQL B7 — согласованное чтение нескольких ключей

Дата: 24 ноября 2026. Экспериментальный SQLite-backed API; это НЕ новый интерфейс SQL и НЕ SQLite-free NativeLog.

## Реализация

Метод Database::read_snapshot(&[(&str, &str)]) возвращает
Vec<Option<Entry>> для **1–16 различных** пар namespace/key
в исходном порядке. Все имена должны быть ASCII-идентификаторами
SedravaSQL длиной 1–128; повтор пары, пустой список и 17 ключей
отклоняются до открытия транзакции.

Используется одна **SQLite read-only DEFERRED transaction**:
первое обращение SELECT фиксирует версию WAL-снимка,
все остальные читаются из той же версии. Если внешний
процесс фиксирует пакет изменений между SELECT внутри метода,
в одном ответе не смешаются старые и новые значения.

Отсутствующий ключ возвращает None, существующая запись,
помеченная удалённой, возвращается как Entry с value=None
и сохранённой revision. Метод не меняет базу, не добавляет
таблиц, не выполняет DDL, не требует миграции и не получает
произвольных полномочий SQL. Ошибки SQLite передаются вызывающей
программе; чтение завершает транзакцию rollback.

## Проверка на VDS

    source "$HOME/.sedrava-dev/env.sh"
    sedravasql_target
    cd "$HOME/.sedrava-dev/sedravasql"
    cargo test --locked --offline --all-targets
    cargo clippy --locked --offline --all-targets -- -D warnings

Дополнительный tests/managed_snapshot_b7.rs проверяет:
- согласованность двух ключей при 180 атомарных конкурентных
  B6-пакетах записи и 900 вызовах snapshot из другого SQLite
  соединения;
- конкретные значения и ревизии до/после серии;
- пустые, неверные, повторённые идентификаторы и превышение 16;
- отличие отсутствующего ключа от удалённого;
- неизменность истории аудита после чтений.

Ограничения: стабильный снимок гарантирован только внутри
**одного вызова** read_snapshot(), а не между HTTP-запросами
и не между SQL-транзакциями. Это не гарантирует свежесть данных
на момент отправки ответа, не проверяет реальное обесточивание,
не защищает от процессов с прямым доступом к файлам БД,
не обеспечивает внешний сетевой ACL и не делает NativeLog
готовым к эксплуатации.
