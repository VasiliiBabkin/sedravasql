# B26 — сокращение повторных проверок схемы при чтении

Базовый коммит: bdb175807375cb8f7b534194737ab72cb11071fd. Обе release-сборки из одного benchmark source, одинаковый Cargo.lock, rustc rustc 1.100.0 (0ef1bc386 2026-11-09). Порядок ABBA; CPU 0, 6 независимых баз по 300 строк на вариант, прогрев 100 вставок и 3 запроса каждого типа на базу. 2 vCPU VDS, параллельная нагрузка (loadavg 3.91–4.27), поэтому вывод относится к этой серии, не универсальному ускорению.

## Изменение

Повторно используем проверенную схему на время одного неизменяемого чтения: индекс проверяется один раз, SHA-256 схемы и namespace вычисляются один раз на индексный lookup/rebuild, а не для каждой строки. Для обычного scan — один раз на страницу. SQL matching использует уже загруженную схему. Каждый stored row по-прежнему декодируется, проверяется digest, набор и типы полей, первичный ключ; чтение poisoned handle запрещено. Нет нового долгоживущего кеша, изменения wire format, журнала, fsync, лимитов или политики транзакций.

Категория и агрегация ускорились в этом эксперименте; SQLite по-прежнему быстрее. Изменение INSERT не интерпретируем как эффект оптимизации: путь записи не менялся, есть вариация fsync и внешней нагрузки. Данные и результаты SQL сверены с SQLite; NativeLog verify и SQLite integrity_check в каждой базе. SQL-поддержка, журнал и гарантии прежние; B25 не подключён. Полный scan, холодный индекс, JOIN, HTTP и большие базы здесь не измерены.

## Проверки

64 прежних теста native-engine + новый B26 regression (260 строк, несколько страниц, tombstone, совпадение scan/index, read-only, cache invalidation, reopen). Clippy --all-targets -- -D warnings PASS. Новый тест первоначально отверг каталог с неверными правами; fixture исправлен на 0700, повтор PASS.
