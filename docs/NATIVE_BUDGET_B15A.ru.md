# B15a — пределы роста нативного журнала

NativeLimits: по умолчанию 64 MiB (67108864 байта) и 65536 подтверждённых транзакций на журнал. Это верхние допустимые параметры записи, а не квота ОС или предел RAM. Через set_limits можно задать более строгие пределы: 8..67108864 байт и 1..65536 транзакций. Они действуют на открытом handle, не записываются в SEDRLOG1, должны повторно задаваться при открытии. Старый журнал выше установленного предела остаётся читаемым: новая транзакция отклоняется до записи первого байта. Идемпотентное повторение ранее сохранённой транзакции разрешено. Учитывается точный размер сериализованного кадра + 36 байт (длина и SHA-256). Usage показывает фактический размер, число транзакций, ключей включая tombstones, квитанций и оставшиеся лимиты. При изменении длины журнала вне эксклюзивного владельца запись отвергается с poisoned handle; не защита от враждебного изменения файла.

CLI: `usage FILE [MAX_BYTES MAX_TRANSACTIONS]`; `batch FILE REQUEST_KEY JSON_FILE [MAX_BYTES MAX_TRANSACTIONS]`. Новая категория Capacity (CAPACITY_EXCEEDED), гарантированное отклонение до записи. Формат и исторические квитанции не изменяются. Это admission control, НЕ компактификация, не ограничение расхода RAM при открытии старых больших журналов. Проверенный формат контрольной точки и политика хранения квитанций — отдельный B15b. Снимок может достичь своего собственного ограничения раньше журнала.

VDS: 42 native Rust + 21 SQLite Rust, строгий Clippy, все 13 предыдущих CLI verification scripts и новый B15a PASS. Точная граница на один байт, потолок транзакций, повтор после reopen, невалидные лимиты, SHA-256 неизменен при отказе.
