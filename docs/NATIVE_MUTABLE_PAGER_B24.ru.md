# B24 — mutable page store and redo WAL

Separate experimental SEDRKV01 file, 4096-byte pages, immutable header with random store identity and fixed slot count, mutable generation page, one checksummed row per slot. Open-addressed SHA-256 key placement with linear probing; tombstones retain key and revision. 8..1024 slots, one serialized row must fit 4048 bytes, 1..16 distinct changes per commit. No dynamic resize, B+Tree splits/merges, overflow pages, SQL integration or durable request receipts. This is a different format from SEDRPG01 and SEDRLOG1. Never open valuable data using it.

Single exclusive handle, private directory and file; trusted same-UID environment. Validate all rows, probe reachability, generation and checksums at open. Read-through cache of at most 32 pages, deterministic eviction, clear after commit. Validate all changes/CAS before writing; commit writes checksummed full after-images to .wal.tmp, fsync, rename to .wal and fsync directory; apply only changed data pages and generation page, fsync data; unlink WAL and fsync directory. On open, a valid published WAL bound to the same immutable header is replayed after checking generation and complete prospective state, then removed. Corrupt WAL fails closed, staging WAL and stale lock require operator review. Recovery on open mutates the pager; pager-verify is NOT a strictly read-only command. An interrupted commit after WAL publication may have committed; inspect revisions on reopen; no exactly-once request receipts. No multiwriter, backup or physical power-loss claim.

CLI: pager-init FILE SLOTS; pager-commit FILE CHANGES_JSON (array of namespace,key,expected_revision,value where value null means delete); pager-get FILE NAMESPACE KEY; pager-verify FILE. Native tests: atomic CAS, cache, full table, corruption; CLI: 3 controlled child-process exits at WAL publication, first page, and data sync; two recovered rows and exactly three changed 4096-byte pages; corrupt WAL rejected with data unchanged. Controlled debug exits, not hardware power failure.

VDS: 62 native Rust tests, 21 SQLite Rust tests, strict Clippy and all native CLI regressions PASS.
