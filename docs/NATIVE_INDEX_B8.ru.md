# NativeLog B8 — проверяемый офлайн-индекс из snapshot

Дата: 24 ноября 2026. Экспериментальный SQLite-free движок, NO-GO для реальных данных.

## Реализация

Новая файловая форма SEDRIDX1 (отдельная от журналов SEDRLOG1 и
снимков SEDRSNP1), неизменяемая и строго ограниченная 64 МиБ.

Команды бинарника sedravasql-native-preview:

    index-create SNAPSHOT NEW_INDEX APPROVED_SNAPSHOT_SHA256
    index-verify INDEX
    index-get INDEX NAMESPACE KEY

Создание разрешено только по заранее подтверждённому 64-значному
SHA-256 B3-снимка. Снимок полностью проверяется, из отсортированных
entries формируется отдельный индекс; в отличие от snapshot,
история idempotency-квитанций в индекс НЕ переносится.

В заголовке индекса хранится schema, SHA снимка, SHA исходного
журнала, sequence и отсортированный каталог namespace/key с
ревизией, относительным смещением, размером и SHA-256 каждой
записи. Далее следуют сериализованные записи и общий SHA-256
файла. Значение может быть null для tombstone; ревизия сохраняется.

Проверка валидирует контрольную сумму файла, размеры, sorted/unique
каталог, непрерывные смещения, контрольные суммы всех строк и
совпадение ключей/ревизий с каталогом.

index-get выполняет **двоичный поиск по отсортированному каталогу,
но перед ним строго проверяет ВЕСЬ индекс**. Следовательно,
стоимость одного запроса всё ещё O(размер файла), а гарантированного
ускорения по сравнению с чтением B3 snapshot НЕ заявлено.

Файл создаётся только в НОВОМ пути в приватном каталоге 0700,
с режимом 0600 и fsync файла/каталога. Файлы-дубликаты, symlink,
hardlink, публичные каталоги, неправильное разрешение SHA
отвергаются. Оригинальный snapshot и исходный native-журнал не
изменяются и не удаляются. Атомарность исходной БД не затрагивается.

## Проверки

    source "$HOME/.sedrava-dev/env.sh"
    sedravasql_target
    cargo test --manifest-path native-engine/Cargo.toml --locked --offline --all-targets
    cargo clippy --manifest-path native-engine/Cargo.toml --locked --offline --all-targets -- -D warnings
    cargo build --manifest-path native-engine/Cargo.toml --locked --offline --bin sedravasql-native-preview
    SEDRAVASQL_NATIVE_BIN="$CARGO_TARGET_DIR/debug/sedravasql-native-preview"       python3 -B scripts/verify_native_index_b8.py

Новые четыре Rust-теста и независимый CLI-прогон покрывают
детерминированное создание на 7–9 транзакциях, стабильные
ревизии активной и удалённой записи, пустой индекс и отсутствие
ключа, полную проверку/поиск, 7 повреждений байтов,
6 усечений, лишние данные, запрет перезаписи и неверного
SHA, права доступа. Существующие тесты B1–B5 и SQLite API
не должны измениться.

## Что это НЕ означает

Это **офлайн-модель дискового индекса**, а не быстрый
случайный on-disk lookup с доказанной асимптотикой,
не индекс для живого писателя, не checkpoint,
не компактификация или восстановление writable NativeLog.
Index НЕ содержит историю квитанций и не подходит для
восстановления идемпотентных транзакций. Он отражает
точно один завершённый snapshot (без обещания актуальности).

Строгая проверка SHA обнаруживает случайную порчу, но не
защищает от злоумышленника с доступом к файлам, способного
пересчитать все контрольные суммы. Не проверены обесточивание
сервера, файловые сбои и долгосрочная совместимость формата.

Дальше: настоящий индекс по смещениям журнала с ограниченным
чтением страниц, прозрачной проверкой актуальности и
доказанным выигрышем, а затем operator-approved checkpoint.
