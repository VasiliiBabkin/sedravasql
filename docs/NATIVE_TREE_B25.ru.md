# B25 — динамическое упорядоченное дерево поверх pager B24

Separate dedicated experimental tree store. Logical leaf/branch nodes are serialized into individual pager slots; values occupy separate slots. Ordered ASCII namespace-free keys (valid_id), fanout 8 separator keys, height <=5, linked leaves, point lookup and half-open ordered range (1..256), CAS updates and tombstones. Insert splits leaves and internal branches, promotes separator keys, creates a new root as needed. All data, changed nodes and metadata are committed atomically via the B24 WAL. Open verifies all reachable nodes, ordered keys, separator boundaries, equal leaf depth, node count, linked leaf chain and presence of data rows. Dedicated trusted store; direct pager writes to reserved namespaces unsupported. Capacity is inherited from B24 (8..1024 total slots including metadata, nodes and rows); serialized values must fit the physical page, additional input limit 3000 bytes. No merge/rebalance on deletion, dynamic file growth, overflow pages, multiwriter, SQL integration or physical power-loss guarantee. CLI tree-init FILE SLOTS; tree-put FILE KEY EXPECTED_REVISION VALUE_JSON (JSON string or null in file); tree-get FILE KEY; tree-range FILE START END LIMIT; tree-verify FILE (may recover WAL). Revisions and tombstones remain durable. A failed initial creation may leave an unusable file; operator review required.

VDS: 120 permuted inserts, 3+ levels, ordered range, updates and reopen; capacity conflict leaves file unchanged; interrupted root split recovered via actual child-process exit and WAL replay; 64 native Rust tests, 21 SQLite Rust tests, strict Clippy and CLI regression suite PASS.
