# B20 — foreign keys and atomic disjoint-row SQL transactions

`ALTER TABLE Child ADD FOREIGN KEY (column) REFERENCES Parent(id)` adds an immutable single-column TEXT reference to a different table's TEXT primary key. The catalog entry is durable; creation checks existing child rows. RESTRICT semantics: missing parent and deletion of a referenced parent fail. No cascade, nullable references, self-references, drop or multi-column key. At most 64 definitions; creation and parent deletion scan at most 4096 child entries (including tombstones). All checks are before append and in replay prepare, see prospective final row values, and apply to typed table mutations as well as SQL. Legacy releases do not know these constraints: downgrade with a constrained journal is unsupported. No frame format change, no change to existing single SQL write fingerprint. Dedicated trusted typed journal; do not directly manipulate internal namespaces.

`sql-transaction FILE REQUEST_KEY STATEMENTS_JSON` accepts 1..15 objects {"sql":"...", "params":[scalar,...]}. Each statement must be INSERT, UPDATE or DELETE, affect exactly one distinct row; UPDATE/DELETE must have PK equality. Statements plan against the same committed starting generation, not sequential read-your-writes. No repeated row address, DDL, SELECT, BEGIN/COMMIT session or savepoints. One frame contains all mutations plus one receipt; FK checks see the whole final state regardless of input order. Any precommit error leaves journal bytes unchanged. Replay uses canonical transaction fingerprint, scoped to same SQL receipt namespace; different input under same key conflicts. Existing frame size and capacity limits apply.

VDS: 55 native + 21 SQLite Rust tests, strict Clippy and all CLI regressions PASS. Verified FK migration rejection on orphan, child write, parent delete, same-frame parent/child insert and delete, bound input, typed write guards, atomic failure, reopen and durable replay. Persistent disk index pages, larger journal architecture and general sequential transactions remain pending. Not production-ready.
