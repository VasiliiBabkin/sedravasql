# B23 — copy-on-write generation refresh

`page-build-log LOG NEW_IMAGE` creates a complete verified SEDRPG01 image directly from an exclusive, verified log handle (canonical SEDRSNP1 digest computed in memory). `page-refresh LOG IMAGE STAGING APPROVED_OLD_SHA256` verifies the old image, matches its journal digest to an exact committed prefix of the current journal, builds and syncs a new image at an unused staging pathname in the same private directory, verifies the new image against the current log, atomically renames it over the approved old image, and syncs the directory. Old readers fail identity checks after replacement. Old and new image refer to immutable generations; SEDRLOG1 remains authoritative and unchanged. On interruption before rename, old image and possibly orphan staging file remain; after rename verify the selected image and log before use. Never blindly delete staging files or stale writer locks. Dedicated trusted private directory required; malicious same-UID manipulation out of scope. No in-place page updates, splits, live SQL index, checkpoint that truncates WAL, automatic recovery, or hardware power-loss guarantee. Full image rebuild is bounded and not a scalability claim.
