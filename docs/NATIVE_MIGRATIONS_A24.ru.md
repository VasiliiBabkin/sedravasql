# A24a — версионирование схем NativeLog

Добавочный механизм миграций с манифестом формата JSON 1. Каждый шаг имеет возрастающий номер (1..128 без пропусков), уникальное имя ASCII (1..64 символа) и ровно один поддерживаемый DDL: CREATE TABLE, CREATE INDEX, ALTER TABLE ADD FOREIGN KEY. Манифест до 64 KiB; проверка структуры/синтаксиса всех шагов до записи. Семантические зависимости и существующие данные проверяются при применении конкретного шага.

```json
{"version":1,"steps":[{"version":1,"name":"products","sql":"CREATE TABLE Products (id TEXT PRIMARY KEY, title TEXT)"}]}
```

```bash
sedravasql-native-preview migration-status DB PLAN_JSON
sedravasql-native-preview migration-apply DB PLAN_JSON
```

DB — существующий NativeLog в приватной директории. Манифест и директория под контролем доверенного оператора; загрузчик не принимает симлинки, ограничивает объём чтения, но не обещает защиты от конкурентной подмены доверенного пути. Не передавать путь от внешних пользователей.

Один шаг = одна атомарная запись каталога + неизменяемая запись истории в той же checksummed frame. Квитанция NativeLog связывает обе записи. История содержит version/name/SHA256/sequence. Хэш вычислен по каноническому JSON структуры шага и доменному разделителю; даже изменение пробелов внутри SQL меняет хэш. Проверка истории сверяет номера, ревизии, последовательность, receipt, текущее состояние применённого каталога и хэш шага. Повторный запуск завершённого плана не записывает данные. Укороченный план, изменённый применённый шаг и дрейф связанного каталога отклоняются. При конфликте или ограничении ресурсов текущий шаг не фиксируется; предыдущие завершённые версии остаются применёнными. Это не атомарность всего манифеста. После сбоя до завершения записи журнал остаётся fail-closed по существующим правилам NativeLog; автоматического ремонта нет.

Нет DROP, RENAME, изменения/добавления столбцов, произвольного DML, downgrade, автоматического baseline существующей схемы или отката. Существующая вручную созданная таблица конфликтует с созданием из плана. Миграции не гарантируют отсутствие сторонних дополнительных объектов; сырые операции с системными namespace — вне доверенной политики. Манифесты хранятся в репозитории приложения и расширяются только добавлением шагов. Старый бинарник может читать NativeLog, но не проверяет версии схем. Не использовать ценные данные. B37 внутренний контракт хранения сохранён; COW не включён.

Испытания: 6 новых тестов (проверка манифеста, отказ ручного baseline, FK/индексы/сохранение данных, точное отсутствие записи при конфликте, лимиты, изменение истории, повторное открытие, injected after_sync с восстановлением версии). Первый прогон тестов отказал из-за прав временной директории и неверного имени переменной fault hook; исправлена только оснастка. Debug fault test не является испытанием аппаратного отключения питания. Полная native regression и strict Clippy на VDS — PASS, логи в evidence/a24-migrations-2026-11-27. Main и версия выпуска не изменены; независимая Forgejo CI пока не подтверждена.
