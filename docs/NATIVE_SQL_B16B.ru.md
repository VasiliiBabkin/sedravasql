# B16b/B16c — native SQL subset

Один SQL statement на вызов, необязательная конечная ;. Ключевые слова без учёта регистра, идентификаторы с учётом регистра. CREATE TABLE с 1..16 столбцами и inline TEXT PRIMARY KEY; INT/INTEGER, BOOL/BOOLEAN, TEXT. INSERT требует полный список столбцов и VALUES одного ряда. SELECT columns/* FROM table [WHERE column op scalar [AND ...]] [ORDER BY column ASC|DESC] [LIMIT 1..256]. По умолчанию 100 строк, сортировка по PK, при совпадении ключа сортировки — по PK. UPDATE SET scalar assignments WHERE predicates; DELETE FROM table WHERE predicates. WHERE обязательно для UPDATE/DELETE. Сравнения = != <> < <= > >=, bool только equality/inequality. Нет NULL, OR, JOIN, агрегатов, GROUP BY, ALTER, DROP, транзакций из нескольких SQL statements, изменения PK, вставки поверх tombstone. Один SQL write до 15 строк (16-я операция — квитанция). Скан до 4096 записей, иначе отказ; PK equality использует прямой поиск. Лимит SQL 16KiB/512 tokens. Ключ запроса обязателен при записи, >=12 символов в native key contract. Хеш ключа отделяет SQL receipts; fingerprint канонического разобранного statement, включая параметры. Квитанция и изменения в одном кадре; повтор после reopen возвращает первоначальный affected/sequence; нулевой affected также получает квитанцию. Никакой SQL поверх недоверенного raw KV в reserved namespaces.

CLI: sql FILE SQL [REQUEST_KEY]; sql-bind FILE SQL PARAMS_JSON [REQUEST_KEY]. PARAMS_JSON — массив int32/bool/text значений. Параметры ? только в позиции scalar literal, не имена таблиц/столбцов/SQL grammar/LIMIT; exact arity, <=32. Проверены payload с кавычкой/SQL-командами как данные, конфликт повторного ключа с изменённым параметром. Не production; CLI/embedding, не сетевой SQL сервер.

VDS: 49 native Rust tests (3 SQL tests), 21 SQLite Rust tests, strict Clippy PASS. 24 строки/10 сравнений SELECT до и после UPDATE/DELETE с независимой SQLite oracle, existing CLI regressions PASS на B16b; повтор SQL oracle после B16c PASS. SQLite не участвует в исполнении SQL.
