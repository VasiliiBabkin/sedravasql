# B21/B22 — страничный образ и дисковое дерево поиска

`SEDRPG01` is a separate immutable read image of one operator-approved SEDRSNP1 snapshot, not a replacement for the writable SEDRLOG1 journal. Fixed 4096-byte pages, 16-byte envelope (magic, page ID, kind, payload length, reserved), 32-byte SHA-256 trailer, zero padding; page zero contains generation metadata (snapshot and log digests, sequence, root, height, count). Leaves carry ordered composite namespace/key and row extent references; internal nodes carry child page IDs and minimum keys. Fanout <=12, <=8 levels, <=32768 pages (128 MiB), serialized row <=400000 bytes. Row payloads can span multiple pages. No global in-memory key directory. Empty tree supported. Each page is checked; open traverses the entire tree, validates ordering, levels, separators, exact page ownership/reachability, row identities and revisions. The verified handle then seeks directly down the tree plus row pages, rechecking page digest and file identity. The source/destination must be private; creation never overwrites. Failed creation can leave an incomplete image; discard after operator review. Source and journal not rewritten. `page-match-log` checks sequence and exact log digest while exclusively opened, rejects stale generation. It does not independently prove a hostile image corresponds to a log; trusted operator-approved inputs only, no authentication against malicious same-UID edits. `page-create SNAPSHOT NEW_IMAGE APPROVED_SHA256`, `page-verify IMAGE`, `page-get IMAGE NAMESPACE KEY`, `page-match-log IMAGE LOG`.

Current limits: one or more dedicated data pages per row, not space-efficient for short rows; full verification on open, no benchmark claim. B+ tree-style read-only bulk-built tree, no leaf sibling traversal, page splitting, update, free list, WAL, buffer pool, disk SQL secondary index, or online checkpoint. Existing SQL execution still reads the native journal. Next stage must integrate durable mutable page generations and transaction/recovery protocol before production. Do not use valuable data.

VDS: 57 native + 21 SQLite Rust tests, strict Clippy and all native CLI regressions PASS. CLI: 160 rows, 178 pages, height 3, <=4 page reads after full verification. Rust: 320 rows, 3 levels, escaped 65536-byte value, tombstone, stale generation, corrupted/truncated image and empty tree PASS. No writable page store claim.
