# SedravaSQL B5.1 — матрица повреждений и неполных файлов

Дата: 23 ноября 2026. Это испытательный набор, не production release.

## Что исследовано

Программа scripts/verify_native_fault_matrix_b51.py вызывает отдельный
CLI-процесс sedravasql-native-preview над временными приватными файлами.

Для пяти workloads созданы 5, 7, 9, 11 и 13 транзакций на двух ключах
с Unicode-значениями. Каждый workload проходит журнал → B3 snapshot →
B4 restore. Результирующий SEDRLOG1 сверяется побайтово с оригиналом,
проверяются SHA-256, значения и воспроизведение старых квитанций.

Затем выполняются негативные пробы: изменения отдельных байтов, усечение
файла, лишний хвост, заранее существующий неполный файл назначения.
Любой испорченный источник должен быть отвергнут без создания
нового назначения; старое назначение должно остаться неизменным.

## Результаты VDS

- 5 успешных циклов восстановления с повторными запросами.
- 145 испорченных снимков с изменённым байтом: отказ.
- 60 усечённых снимков: отказ.
- 15 снимков с лишним хвостом: отказ.
- 20 существующих частичных назначений: не перезаписаны.

Все входы находятся в приватном TemporaryDirectory mode 0700.
Ни FastPanel, ни публичные сайты, ни production базы не затронуты.

    SEDRAVASQL_NATIVE_BIN="$CARGO_TARGET_DIR/debug/sedravasql-native-preview" \
      python3 -B scripts/verify_native_fault_matrix_b51.py

## Ограничения

Испытания исследуют только уже записанные файлы на диске.
Они не моделируют аварийный SIGKILL в момент fsync, реальное
отключение питания, сбой файловой системы или отказ железа.
Тесты не подтверждают полноту защиты от враждебного писателя
того же пользователя, не доказывают долговечность транзакций,
не создают checkpoint/compaction или собственный дисковый индекс.

Следующий этап B5.2 — контролируемые точки отказа внутри операций,
отдельная модель crash consistency и подтверждение восстановления.
Пока использование для ценных данных остаётся NO-GO.
