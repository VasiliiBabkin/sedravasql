# NativeLog B9 — прямое дисковое чтение строк из проверенного индекса

Дата: 24 ноября 2026. Экспериментальный SQLite-free preview, НЕ production.

## Реализация

B9 сохраняет формат B8 SEDRIDX1, не меняет журнал и не делает
нового несовместимого файлового формата.

Новый VerifiedIndexReader:
1. open(path): проверяет приватность файла и каталога, inode,
   всю структуру индекса, SHA-256 каждой строки и целого файла;
   повторно сверяет SHA-256 на открытом файловом дескрипторе;
   читает отсортированный каталог ключей в RAM и фиксирует
   inode/size/mtime/ctime.
2. get(namespace,key): двоичный поиск в RAM-каталоге,
   затем seek на точное смещение на диске и read_exact
   только нужной строки. Проверяются SHA-256 строки,
   namespace/key, revision, метаданные до/после обращения.
3. row_bytes_read: счётчик прочитанных байтов в секции строк
   после открытия (не включая первичную проверку файла).

Дополнительная CLI-команда:

    sedravasql-native-preview index-get-many INDEX REQUESTS_JSON

REQUESTS_JSON — массив 1–256 пар namespace/key в формате JSON,
размером до 16 КиБ. CLI проверяет индекс один раз, выполняет
все обращения через один дескриптор и возвращает JSON с
rows, queries, row_bytes_read, index_bytes и index_sha256.

Команды index-get/index-verify/index-create B8 сохранены.
Старый index-get по-прежнему выполняет полную проверку
при каждом запуске процесса.

## Фактическая проверка VDS

64 записи в четырёх нативных batch-транзакциях.
Индекс размером 79 924 байта.
54 запроса через один открытый индекс: 4 найденных и 50 отсутствующих.
Прочитано из data-секции после открытия 4 358 байт
(только четыре выбранные строки).

Дополнительные четыре Rust-теста: выборочное чтение,
отсутствующие ключи, подмена inode после открытия,
изменение файла после открытия, ошибочные данные
и проверка отказа. CLI-тест дополнительно проверяет
повреждённый индекс, неверный входной JSON и лимит запросов.

Это доказывает ограниченное чтение строк для множества запросов
в одной сессии, но НЕ доказывает выигрыш времени по сравнению
с SQLite и НЕ исключает полной проверки при каждом новом open.

## Ограничения

Внутри одной сессии: O(log N + размер строки) по структурным
операциям, но временная производительность не измерялась
по сравнению с другим движком. RAM каталога растёт с числом
ключей; общий размер индекса ограничен 64 МиБ.

Сравнение inode/size/mtime/ctime и SHA-256 выбранной строки
не защищает от злоумышленника с тем же UID, способного
восстановить метаданные и пересчитать контрольные суммы.
Изменение другой строки после open может остаться
незамеченным до её чтения/повторного открытия.
Допустим только доверенный неизменяемый офлайн-файл.

Пока нет синхронизации с коммитом NativeLog, индекса для
живого писателя, checkpoint, compact, сохранения истории
квитанций в индексе, серверной авторизации и гарантированной
устойчивости при физическом обесточивании.
