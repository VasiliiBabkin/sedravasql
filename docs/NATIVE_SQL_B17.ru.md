# B17 — агрегаты, GROUP BY и план доступа

SELECT COUNT(*)/COUNT(column), SUM/AVG(INT column), MIN/MAX(column), optional AS alias. All columns are non-null; COUNT(column) validates column and counts rows. SUM uses i64 (bounded by <=4096 scanned rows and i32 values); AVG uses f64. Empty ungrouped selection yields count 0 and null for other aggregates; empty grouped selection yields zero rows. GROUP BY one scalar column, projected nonaggregate columns must match it; deterministic group order by typed key; ORDER BY projected label/alias ASC/DESC, stable ties. LIMIT after grouping, <=256 results. Result kind aggregate_rows with JSON cells (including null and numeric values beyond i32); ordinary rows and write receipts unchanged. No HAVING, JOIN, DISTINCT, nested aggregates, secondary indexes or cost optimizer. The explain CLI reports actual access strategy (PK equality vs bounded table scan), aggregation, grouping, sort, limit; it checks syntax/table/predicates, not all projection semantics. No write or row scan for explain. Existing statement and journal limits apply. Dedicated trusted journal only.
