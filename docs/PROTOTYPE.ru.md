# SedravaSQL 0.1: как попробовать прототип

**Важно:** исходники экспериментальные, сборка и тесты пока не подтверждены.
Нет релиза, резервного копирования и гарантий сохранности. Используйте
только отдельные, неважные тестовые данные.

## Что это сейчас

Пока это не полноценная универсальная SQL-СУБД. Код реализует встроенную
SQLite-базу с текстовыми ключами и значениями. Поверх неё предлагаются
безопаснее управляемые операции, журнал и проверка удаления перед выполнением.

Каждое сохранение через API должно добавлять запись аудита в той же
транзакции. Массовое удаление должно сначала получить токен предпросмотра,
затем проверить его ещё раз внутри транзакции записи. **Это проектные свойства
написанного кода, а не уже подтверждённые тестами гарантии.**

## Что потребуется

- Rust 1.89+ и Cargo
- Компилятор C для сборки встроенной SQLite
- Git
- Python 3, если запускать скрипт быстрой проверки

Все зависимости Rust описаны в Cargo.toml. Файл Cargo.lock пока не создан:
версии транзитивных зависимостей не зафиксированы. Это технический долг
до первой проверенной сборки.

## Команды

Склонируйте проект и переключитесь на ветку с прототипом:

    git clone https://github.com/VasiliiBabkin/sedravasql.git
    cd sedravasql
    git fetch origin feat/prototype-v0.1
    git switch feat/prototype-v0.1
    cargo build
    cargo test

После сборки на Linux/macOS программа находится в target/debug/sedravasql
(в Windows — target\debug\sedravasql.exe). Пример ниже для Linux/macOS.

Создание базы:

    ./target/debug/sedravasql init --db demo.db

Сохранение двух записей:

    ./target/debug/sedravasql put --db demo.db --key note:1 --value "Первая заметка"
    ./target/debug/sedravasql put --db demo.db --key note:2 --value "Вторая заметка"

Чтение:

    ./target/debug/sedravasql get --db demo.db --key note:1
    ./target/debug/sedravasql list --db demo.db --prefix note:

Ограниченный SQL-запрос только на чтение:

    ./target/debug/sedravasql query --db demo.db --sql "SELECT key, value FROM sedravasql_kv WHERE key = ?1" --param note:1

Журнал операций:

    ./target/debug/sedravasql audit --db demo.db

## Как работает удаление

Первый вызов ничего не удаляет:

    ./target/debug/sedravasql preview-delete --db demo.db --prefix note:

В ответе JSON будут количество записей и поле token. Скопируйте значение
token (64 шестнадцатеричных символа) и выполните:

    ./target/debug/sedravasql apply-delete --db demo.db --prefix note: --token ВАШ_ТОКЕН

Если записи изменились, удаление будет отклонено. Также операция не
выполняется при нулевом количестве совпадений или более 10 записей.
Пустой префикс запрещён.

**Токен — не пароль и не разрешение на удаление.** Это контрольный отпечаток
состояния базы. Копии одного файла сохраняют общий идентификатор базы.
Восстанавливать удалённые данные программа пока не умеет.

## Проверка

    cargo fmt --all -- --check
    cargo test --all-targets
    bash scripts/smoke.sh

Последняя команда создаёт временную демонстрационную базу, проверяет отказ
по устаревшему предпросмотру и успешное удаление после свежего предпросмотра.

Пока результаты этих команд **не зарегистрированы**. Для подтверждения нужны
версии Rust/SQLite, окружение и сохранённый вывод. См. docs/VERIFICATION.md.

## Ограничения

- Данные лежат в незашифрованном файле SQLite.
- Нет ролей, паролей, сетевого API и разграничения доступа.
- Доступ к файлу напрямую через SQLite обходит управляемый журнал.
- Журнал хранит ключи и SHA-256 значений, но не старые значения для отката.
- Хеши не защищают от подбора коротких или предсказуемых значений.
- Нет резервирования, проверенного восстановления или гарантий для отказов питания.
- SELECT не является песочницей для недоверенных SQL-запросов.
- Максимум 1000 строк в ответе списка/запроса; 10 000 при предпросмотре;
  10 строк за одно массовое удаление.
- Максимум 256 байт UTF-8 в ключе и 1 МиБ UTF-8 в значении.

Для разработки см. docs/ARCHITECTURE.md и docs/THREAT_MODEL.md.
