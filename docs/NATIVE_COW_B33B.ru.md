# B33b — отдельные страницы долговременных квитанций

Исследование от B33 3779d49. При 49-й квитанции атомарно переходим с SEDRHDR4 на SEDRHDR5; старые заголовки 1–4 читаются. V5 manifest содержит root/count цепочки SEDRREC1; до 48 записей на страницу, каждая 72 байта. При добавлении копируется только неполная последняя страница; полные страницы сохраняются. Ссылки убывают, checksum, identity, generation, размеры, порядок и уникальность проверяются; страницы включены в общую карту владения. COW allocation не перезаписывает страницы текущего поколения. Compact copy переносит всю историю. Максимум 32768 квитанций (ограничения MAX_PAGES также действуют); без вытеснения; новый ключ при заполнении отклоняется. Повтор старого ключа доступен. Это цепочка с проверяемой историей, не дисковый B-tree индекс; полная валидация/поиск пока линейны. Фактическая граница 32768 не прогонялась; проверено отклонение manifest с count выше лимита.

Целевые B33/B33b: 9 тестов PASS, включая два служебных child. 240 квитанций, reopen на границах страниц, replay всех 240 после compact, компактная база 7 data pages (включая 5 страниц квитанций), до compact менее 30 pages. Повреждения checksum-valid self-link, пересечение с data root, превышение count; шесть process-exit сценариев при миграции v4 и замене хвоста. Прежняя B33 проверка лимита 48 заменена проверкой перехода на v5. Не физическое отключение питания; stale lock/stage удаляются оператором после проверки завершения процесса. SQL не переключён. Исторические произвольные SQL-ответы пока не являются частью формата квитанции.

Воспроизведение: cargo test --manifest-path native-engine/Cargo.toml --locked --offline --test cow_b33 --test cow_b33b.
